# 用戶身份與信箱驗證說明

## 如何辨識「真的是學校信箱」？

平台採用**網域後綴白名單**判斷是否為學校／學術機構信箱：

- **做法**：註冊時檢查 Email 的網域（`@` 後面的部分）是否落在預設的學術後綴清單內。
- **目前涵蓋**：`.edu`、`.edu.tw`、`.edu.cn`、`.ac.uk`、`.ac.jp`、`.ac.cn`、`.edu.hk`、`.edu.sg`、`.ac.kr` 等。
- **結果**：若符合，系統會將該帳號標記為「機構信箱」並顯示標章；**無法 100% 區分個人信箱**，但可對「已知學術網域」給予標章，提升信任度。
- **建議搭配**：**信箱驗證**：註冊時僅使用信箱驗證（寄送 6 碼驗證碼至信箱），完成後標記「信箱已驗證」。本平台不使用手機驗證。

後端邏輯在 `server/index.js` 的 `isInstitutionalEmail()`；若要新增學校網域，可調整 `INSTITUTIONAL_DOMAIN_SUFFIXES` 陣列。

## 本次優化內容（層次化註冊與標章）

### 一、基礎必填 (Basic)
- **真實姓名／暱稱**：必填，平台顯示用。
- **電子信箱**：必填；若為學術網域則自動獲得「機構信箱」標章。
- **手機號碼**：選填（僅作為聯絡用，無驗證流程）。

### 二、學術與專業 (The AcadeBee Edge)
- **ORCID ID**：選填，欄位已保留，未來可串接 ORCID OAuth 驗證。
- **技能標籤**：從預設清單多選（如 SPSS、LaTeX、生醫論文編修等），利於任務媒合。
- **學位已驗證**：欄位已保留，未來可改為「上傳證明＋後台審核」後設定。

### 三、資料庫變更
- 請先執行：`database/migrations/001_user_profiles_and_skills.sql`，會新增 `users` 欄位與 `skill_definitions`、`user_skills` 表。

### 四、註冊時先驗證（僅信箱驗證）
- **註冊流程**：在註冊頁先填寫**電子信箱** → 點「發送驗證碼」→ 信箱會收到一組 **6 碼** → 在頁面輸入「信箱驗證碼」→ 再填寫姓名、密碼、手機（選填）等其餘欄位 → 點「建立帳號」。**信箱驗證通過後才會建立帳號**，新帳號的信箱即為已驗證狀態；手機為選填，僅供聯絡用。
- **資料表**：需執行 `database/migrations/003_registration_codes.sql` 與 `database/migrations/004_registration_email_only.sql`（使註冊僅使用信箱驗證碼，手機/手機驗證碼欄位可為空）。

### 五、個人資料頁的驗證（補驗證用）
- **信箱驗證**：若帳號是舊版註冊、尚未驗證，可於個人資料頁點「發送驗證碼至信箱」→ 輸入 6 碼完成驗證。
- **環境變數**（見 `.env.example`）：寄信需設定 `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`, `FRONTEND_URL`（Gmail 需用應用程式密碼）。
- 未設定 SMTP 時，後端仍會產生驗證碼並印在主機 log，方便開發測試。
- **資料庫**：需先執行 `database/migrations/002_verification_tokens.sql`。

### 六、畫面與 API
- **註冊頁**：新增手機、ORCID、技能多選；說明使用 .edu／學校信箱可獲標章。
- **個人資料頁**：顯示機構信箱／信箱已驗證／學位已驗證標章；可發送驗證碼至信箱並輸入 6 碼完成驗證。
- **驗證信箱頁**：`/verify-email?token=xxx`，點驗證信連結後顯示驗證結果。
- **Header**：登入後若為機構信箱，顯示「機構✓」小標章。
- **API**：`GET /api/skills`、`POST /api/send-verification-email`、`POST /api/verify-email`、`GET /api/verify-email?token=`。
